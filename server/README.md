# Ownquiz push server

Small Web Push server for the Ownquiz PWA. It stores browser push subscriptions and sends the daily study reminder even when the app is closed.

## Requirements

- Node.js 20+
- HTTPS in production (browsers only allow push subscriptions on secure origins)

## Setup

```sh
cd server
npm install
npm run keys
```

Copy `.env.example` to `.env` and fill in the generated VAPID keys.

| Variable | Purpose |
| --- | --- |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | Generated by `npm run keys`. Keep the private key secret and stable; changing it invalidates existing subscriptions. |
| `VAPID_SUBJECT` | `mailto:` address identifying you to push services. |
| `ALLOWED_ORIGINS` | Comma-separated browser origins allowed to call the API, e.g. `https://sakul-dev.github.io`. Defaults to `*`. |
| `SITE_URL` | URL opened when a notification is tapped. |
| `DATA_DIR` | Where `subscriptions.json` is stored (default `data/`). |
| `ADMIN_TOKEN` | Optional; enables `POST /api/test` when set. |

Run it:

```sh
npm start
```

Development mode with auto-restart:

```sh
npm run dev
```

Tests:

```sh
npm test
```

## API

- `GET /api/vapid-public-key` returns `{ "publicKey": "..." }`.
- `POST /api/subscribe` upserts a subscription by `endpoint` and returns the next due time:

  ```json
  {
    "subscription": { "endpoint": "https://...", "keys": { "p256dh": "...", "auth": "..." } },
    "time": "18:00",
    "timezone": "Europe/Berlin",
    "url": "https://sakul-dev.github.io/Ownquiz/",
    "title": "optional custom title",
    "body": "optional custom text"
  }
  ```

- `POST /api/unsubscribe` with `{ "endpoint": "https://..." }`.
- `GET /api/health` returns `{ "ok": true, "subscriptions": 1, "now": "..." }`.
- `POST /api/test` with an `X-Admin-Token` header sends a test push to every subscription (disabled unless `ADMIN_TOKEN` is set).

## Client integration

`sw.js` already handles the `push` event, so the client only needs to create and register the subscription. Call this after notification permission is granted (for example inside `handleNotifyEnable` in `src/script/notifications.js`):

```js
const PUSH_SERVER = 'https://your-server.example.com';

function urlBase64ToUint8Array(base64String) {
  const padding = '='.repeat((4 - (base64String.length % 4)) % 4);
  const base64 = (base64String + padding).replace(/-/g, '+').replace(/_/g, '/');
  const raw = atob(base64);
  return Uint8Array.from(raw, character => character.charCodeAt(0));
}

async function enableServerReminders(time) {
  const registration = await getNotificationRegistration();
  const { publicKey } = await fetch(PUSH_SERVER + '/api/vapid-public-key')
    .then(response => response.json());
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: urlBase64ToUint8Array(publicKey)
  });
  await fetch(PUSH_SERVER + '/api/subscribe', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      subscription: subscription.toJSON(),
      time: time,
      timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
      url: new URL('./', location.href).href
    })
  });
}
```

Disable:

```js
async function disableServerReminders() {
  const registration = await getNotificationRegistration();
  const subscription = await registration.pushManager.getSubscription();
  if (!subscription) return;
  await fetch(PUSH_SERVER + '/api/unsubscribe', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ endpoint: subscription.endpoint })
  });
  await subscription.unsubscribe();
}
```

Notes:

- Re-POST `/api/subscribe` when the reminder time changes; it upserts by endpoint.
- Keep the existing in-app timer as a fallback while the app is open. Both use the same notification tag, so they replace each other instead of stacking.
- The server cannot see local quiz progress (`state.cards` / `state.known`), so pushes use the generic text unless you pass `body` when subscribing.
- iOS requires the PWA to be installed to the Home Screen (iOS 16.4+) before push works.
- Subscriptions can expire; re-subscribing on app start is a good idea.

## Scheduling

Each subscription stores an IANA timezone and a local `HH:MM`. Every 30 seconds (`TICK_MS`) the server checks for due reminders, sends the push, then schedules the next local occurrence. Timezone math is DST-safe and supports half-hour offsets. Reminders more than 6 hours late (e.g. after server downtime) are skipped. Subscriptions that push services report as gone (404/410) are deleted automatically.

## Deploying

GitHub Pages only serves static files, so this server needs a Node host:

- Render / Fly.io / Railway with a persistent volume for `data/`
- A VPS or Raspberry Pi behind Cloudflare Tunnel
- Any other host that keeps `data/` across restarts and terminates HTTPS

Set `ALLOWED_ORIGINS` to your Pages origin, point `PUSH_SERVER` in the client at the deployed URL, and set `TRUST_PROXY=1` when running behind a reverse proxy so rate limiting sees real client IPs.
